## 本轮目标

完成 **Electron Desktop 主线产品化的第一轮**。

当前已经存在：

* `apps/stage-web`
* `apps/stage-desktop`
* Electron BrowserWindow
* preload bridge
* `contextIsolation: true`
* `sandbox: true`
* `nodeIntegration: false`
* Windows foreground app/title 获取
* Autonomous Speak vertical slice
* Conversation / Settings / Speech 等已有能力

目前启动仍然需要分别运行：

```bash
pnpm dev
pnpm dev:desktop
```

Electron 与 Browser 共用同一套 `stage-web` renderer。

本轮不要继续停留在“Electron 壳可以打开”的状态，而是让：

**Aisling Desktop 正式成为项目后续的主要运行入口。**

但注意范围：

> 本轮只做到“稳定主线宿主”。

不要陷入 Electron 基础设施无限完善。

下一阶段仍然要尽快进入 Live2D Renderer。

# 2. 收束 Desktop 启动链路

当前：

```text
pnpm dev
+
pnpm dev:desktop
```

目标是在开发阶段至少形成一个明确的 Desktop 主入口，例如：

```bash
pnpm dev:desktop
```

或者仓库现有结构下更合理的等价命令。

该命令应负责：

```text
启动 Desktop 所需 renderer/runtime
→ 等待依赖 ready
→ 启动 Electron
→ 打开 Aisling Stage
```

不要要求开发者手动：

1. 开一个终端运行 Vite
2. 等待端口
3. 再开第二个终端
4. 启动 Electron

需要有合理的：

* child process 生命周期管理
* ready 等待
* Electron 退出后的开发进程清理
* 启动失败日志

不要靠固定 sleep 猜测 Vite 已启动。

---

# 3. 明确 Development / Desktop Runtime 边界

整理当前 Electron 对 Stage 的加载方式。

Development 可以继续使用 Vite dev server。

但代码结构上应明确区分：

```text
development
→ loadURL(dev server)

desktop / packaged-ready path
→ load local built renderer
```

本轮不要求真正发布 installer。

但不能继续把 Electron 永久绑定在：

```text
localhost:5174
```

这样的开发假设上。

至少把正式 Desktop 加载路径设计并落到代码中，使未来 `stage-web build` 可以直接被 Electron 承载。

尽量复用现有 stage-web，不复制 renderer。

---

# 4. 处理 Desktop 数据生命周期

重点检查：

* Settings
* Provider configuration
* Conversations
* 当前 localStorage

当前 Browser 与 Electron 如果因为 origin 不同形成两份数据，需要处理。

目标不是现在引入复杂数据库。

目标是保证：

> Aisling Desktop 成为主入口后，Settings 与 Conversation 有稳定、可解释的数据归属。

优先采用当前架构下最小、低风险方案。

可以：

* 保持 renderer persistence，但统一 Desktop origin / storage path
* 或建立非常薄的 Desktop persistence bridge

具体选择必须根据现有实现判断。

不要为了“架构漂亮”直接引入 SQLite、ORM 或复杂 repository layer。

必须保证已有用户配置和 conversation 不被无意义破坏。

如果涉及迁移，做最小兼容迁移。

---

# 5. 保持 Browser Stage

Browser Stage 暂时不要删除。

定位调整为：

```text
Electron Desktop
= primary runtime

Browser Stage
= development / lightweight entry
```

两者继续复用：

* Stage UI
* Conversation UI
* Settings
* Character presentation renderer
* Runtime-facing renderer code

Electron main / preload 只负责桌面宿主和系统能力。

不要把：

* Character rendering
* Live2D
* UI state
* Conversation rendering

搬入 Electron main process。
