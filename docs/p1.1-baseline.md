## 当前结构与职责

```text
kernel.exe：固定外部 HWND -> UIA / mic / headphones -> Playing media -> capture metadata
  -> desktop-activity.cjs：请求序号、超时、规范化和正文指纹
  -> preload / IPC：固定桥接接口与 main 来源校验
  -> desktop-observations.ts：对象、版本、稳定性、候选选择和生命周期
  -> autonomous.ts：quiet / duplicate / ready / busy -> Jev -> 0.65 / cooldown
  -> 媒体生成前重新采样核验
  -> Core handleAutonomous：只将 candidate source/change/target 交给 Chat
  -> Stage：媒体交付前核验、取消、显示与会话保存
  -> registry complete：成功归属、待发版本淘汰、可选近期回复
  -> Speech / Emotion：正常输出副作用；Live2D 读取呈现信号
```

| 模块 | 实际责任与边界 |
| --- | --- |
| Desktop Awareness | Electron 控制原生进程和采样；前台 UIA、媒体、mic、idle、音频设备是组合快照，不是语义情境。浏览器 Stage 无桌面权限。 |
| Candidate / Observation | Candidate 是单个快照绑定目标；objectId 指窗口容器或曲目，candidateId 指版本／机会。registry 唯一持有 reserved/handled/superseded、交付时间、缓存判断与摘要。 |
| Jev 自主判断 | main 校验目标与采样一致，发送 candidate、mic/idle 背景、授权的同目标近期回复；返回 shouldInterrupt，不输出语义对象。Emotion 的 Jev 调用是独立用途。 |
| Chat Runtime | Core 负责 Persona、消息组装、Provider/Tool loop、生命周期和最多 40 条模型上下文。自主回合只接受候选，排除普通会话历史和其他桌面来源；普通用户回合保留历史。 |
| Stage / Delivery | Stage 管理单轮 busy、取消、部分／最终显示和会话保存调用。非空且未取消的成功输出才归属候选。保存为 best-effort，交付不证明磁盘写入或 TTS 成功。 |
| Conversation / Context | 会话后端每会话最多 200 条，Core 上下文最多 40 条；一个负责持久化与 UI，一个负责模型上下文，不是重复的语义 Memory。取消或偏好在途更新时通过 resetHistory 同步。 |
| Interaction Preference / Memory | whole-message quiet/normal/invited 是本地明确指令。偏好跨会话切换和 Awareness 开关，但不跨 renderer 重启；invited 不提高阈值或频率。当前无独立 EventMemory、长期 Memory 或语义情境管理器。 |
| TTS / Live2D / Emotion | Speech 管理语音生命周期与播放，提供 speaking/音量；Emotion 使用完成后的会话评估并平滑呈现；Live2D 负责表情、口型、姿态和交互。它们不选择自主回复对象，本轮不改这些功能。 |

## 已建立的 P1/P1.1 行为

- 前台按 app/HWND 关联对象，按完整标题和空白归一化 UIA 指纹区分版本。最多 32 条观察，未见版本十分钟过期，保护在途 reserved。
- 媒体按规范化 app/title/artist 确认唯一身份；两次连续采样确认，去除重复枚举，竞争或不完整身份不猜测。媒体应用 UIA 不独立制造歌词机会。
- 媒体在生成前与交付前核验；采到过时、缺失或歧义身份则撤销输出。并发采样共享一个 native read。
- 已知前台对象的新版本需两次连续 fresh capture；首次对象出现保持原机会。成功回复消耗同 foregroundScope 下已有待发版本；离开已评论 scope 或出现较新稳定版本也淘汰积压候选与评分。
- 成功交付归属明确 candidateId；失败、空回复、取消不写成功事实。近期回复参考默认关闭，摘要脱敏并限制到 240 字符／十分钟；关闭后本地生命周期仍保留。
- quiet、busy、duplicate、cooldown、ready、revision 和快照一致性门控保留。阈值 0.65，默认 cooldown 30 秒；没有改 Prompt、Persona 或策略。
- P0.5 起始的诊断默认关闭，当前记录 candidate 协议；标题与正文只留长度／指纹，回复正文另行显式授权。replyTarget 仍为 unknown。

用户报告 P1/P1.1 初步真实桌面验收良好；P1 的切歌目标、同曲歌词循环、静态桌面和新网页已有具体反馈。收尾没有新增真实模型调用，也没有新取得逐项 P1.1 实测日志。自动测试的场景与模型响应由 Mock 构造，不等同于模型语义能力验收。

这些是 L1 的采样变化归因、目标绑定和时效控制，不能描述为完整 L2 情境语义理解。

## 清理清单与保留原因

- 删除无调用的旧 PowerShell foreground.ps1；唯一生产采集路径为 kernel.exe。
- 删除 AutonomousStimulus.activity、controller latestContext、无消费者的 lastAutonomousAt 和重复 scores 副本。模型输入不变，分数只由观察缓存持有；smoke 从决策记录读取分数。
- pageIdentity 改名 foregroundScope；内部 probe 使用 scope，避免把 HWND／标题范围宣称为网页语义身份。
- 移除诊断指纹函数的无消费者导出、诊断白名单中过时 micCount/micFingerprint、Stage 中恒成立的 autonomous kind 检查。
- 修正 Core 类型注释、正式偏好说明、README 的旧 idle 阈值和 cooldown；桌面宿主文档改为当前路径，P0.5 统计和 Observation Continuity v0.1 明确归档／替代。
- 同步生产 smoke 的当前模块开关、SpeechBubble DOM 和明确 Mock Provider；保留搜索 relay、存储、输入、模式切换和回复设置验证。
- 保留配置迁移和旧用户历史授权，它们有真实持久化消费者。保留 Conversation 与 Core 的分层历史，保留 Stage awarenessRevision 与 controller revision：前者防 start/stop IPC 乱序，后者防在途判断失效，职责不同。
- 保留 main/renderer 的目标校验：不同执行环境与信任边界，各自必须验证，不为缩短代码绕过校验。
- 原生采样、Prompt、阈值、媒体规则、近期回复、Interaction Preference 及 TTS/Live2D/Emotion 的已成立行为不变。

## 下一阶段讨论所依据的限制与技术债务

1. 已可靠：明确候选与目标输入、局部生命周期、缓存失效、媒体时效、成功归属、本地正式保护与可回溯诊断。
2. 未解决：2000 字符 Name 采样可能混入工具栏／缩略图；同标题稳定 UIA 噪声与真实滚动无法可靠区分；窗口／标题不是网页身份。生成期间或离开前有意义的待发内容可能被淘汰，后续未见过的稳定内容仍可获得机会。
3. 未解决：Playing 元数据是否真实及时、不可观测切歌、持续竞争媒体身份、浏览器播放媒体时 app 级 UIA 抑制误伤、有限 retention 后的重开，以及模型实际回复语义偏移。
4. 技术债务：Provider 没有真正取消协议；撤销只抑制交付，上游工具／网络仍可能完成。UIA 读取可阻塞；存储为 best-effort；自主 quiet 不停止已播放语音。宿主 HTTP TTS relay 与既有 Live2D 断言不匹配仍独立存在。

本报告不提出新 Memory 系统、情境语义分类或 P2 实施方案。
