# Context：历史验证与限制

此页归档 v0.3.5 前后的工程结论。当前契约见 [Context 与持久化](../context-phase-one.md)，不要把历史计数或诊断字段当成当前版本的接口。

## 已修复的持久化边界

历史问题包括：写失败后新会话无法继续访问、读取失败后用空状态覆盖未知数据、恢复仅保留 50 个会话、旧格式迁移每次生成不同身份、保存空 assistant 输出、Desktop 直接覆写可能留下截断文件。现有失败内存状态、严格读保护、稳定迁移、完整恢复、空回复处理与临时文件替换由长期回归测试保护。

用户输入与最终角色输出保留实际追加时间；旧消息和旧迁移会话不伪造“现在”的历史时间。时间边界、来源角色和原始引文不能用相关性排名替代。

## 早期本地测量

当时 Node 24.12.0，预热后测量 Context 组装，不包含启动、存储或网络：

| 完整历史条数 | 选中条数 | 历史估算单位 | p50 / p95 / max ms |
| --- | ---: | ---: | --- |
| 100 | 100 | 1890 | 0.048 / 0.296 / 0.862 |
| 20000 | 204 | 4080 | 0.074 / 0.254 / 1.297 |

另一次 200 次 Context、30 次内存持久化测量中，20000 条历史组装 p95 为 0.332 ms；约 2.8 MB JSON 的完整内存 save p95 约 33.6–53.7 ms，取决于会话分布。整文件同步读写随总记录增长，内存替身不代表真实 localStorage、磁盘或 IPC 成本。不同时间的 0.254 与 0.332 ms 不能当作回归结论。

早期按固定 40 条裁剪与后来 token 窗口的输入长度不同，未建立公平性能前后对照，不报告性能提升倍数。字节估算不是精确 tokenizer 或跨模型上界。

## 真实模型小样本

曾使用 qwen-plus，对“近期约定在第 40 条之外”“追问已交付自主发言”“B 候选不得混入旧 A 候选”三个合成用例分别前后各一次，共 6 次成功请求。词面检查分别为未答出→答出、未答出→答出、通过→通过。

对应请求耗时约为 1294→1425、1463→1432、1022→1107 ms，首文本约为 683→939、640→663、433→481 ms。样本少且内容不同，不能证明稳定延迟收益或所有回复正确。另一次 OpenAI 端点尝试 HTTP 401，不属于有效语义结果。

## 原生 Candidate 冒烟限制

默认生产冒烟曾通过，但可选 Candidate 冒烟出现首次已交付、期望的同 ID duplicate 不存在。它依赖真实前台／媒体在观察期内稳定，且等待条件可能先被其他候选的 duplicate 满足；不能单凭该失败认定 Context 回归。

稳定输入的 Controller、Registry、Stage 测试提供确定性门控覆盖。真实桌面长时稳定性、全部硬件／声卡行为、断电持久性、多实例并发写入及跨 Provider 效果仍未完整验证。历史基准脚本和原始日志不进入正式运行或发布源码。
